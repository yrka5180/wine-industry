# 黄酒生产监测试点与收益验证

日期：2026-09-30。本文是建议方案，不是已经获得工厂确认的实施计划。数量、时间和门槛均可在基线调查后调整。背景与证据见[调研报告](research-report.md)和[材料索引](evidence-register.md)。

## 一、一次只验证一个主要问题

建议二选一作为首期主线：

**A：批次过程监测。** 问题是“能否更早发现一类可干预的偏差，并减少复盘时间或实际损失？”前提是可以获得批次化验、操作记录和明确的质量判定。

**B：CIP 与分项计量。** 问题是“在不降低清洗效果的前提下，能否减少某类可重复清洗任务的水汽或时间消耗？”前提是存在适用的清洗回路、可安装的测点和质量负责人。

不能在同一期同时承诺发酵品质预测、电子鼻污染识别、全厂预测性维护和自动生产控制。先证明其中一件事有用。

## 二、入厂前需取得的基线

| 材料 | 需要回答的问题 | 缺失时的处理 |
| --- | --- | --- |
| 产品与工艺路线 | 哪个品种、哪个阶段、哪类容器？完整周期多长？ | 不制定统一工艺阈值 |
| 近一个完整生产周期的异常/损失记录 | 损失发生在哪个工序？能否干预？ | 先建立损失记录，不宣称降低损耗 |
| 批次与检验数据 | 原料、容器、化验样品和最终结果能否对应？ | 先补身份和时间关联 |
| PLC/仪表点表与接口 | 哪些变量已测，精度/校准状态如何？ | 优先复用，必要时现场对测 |
| 清洗程序与现有验证要求 | 哪些条件由质量部门批准，谁有权修改？ | 首期只采集，不更改清洗逻辑 |
| 水电汽分项计量 | 统计边界是否明确，能否与生产任务关联？ | 先装/核对计量，不直接套行业节省率 |
| 安装与运维报价 | 是否包含卫生接口、校准、耗材、停线与服务？ | 不用裸芯片单价做预算 |
| 数据与网络要求 | 是否允许出厂，保留多久，谁可访问？ | 默认本地/获批环境，不上传配方和原始生产数据到公开仓库 |

把损失拆成明确口径：原料与物料损失、包材损失、返工成本、报废、计划外停机、质量复核工时。财务与生产负责人确认哪些能形成实际现金改善，哪些仅是能力储备或时间释放。

## 三、范围与阶段

### 3.1 建议规模：用于验证工程可用性，不代表统计充分

A 路线可先选 **5–10 个有代表性的生产容器**，尽量限制在一个主要产品与可比较工艺范围。先采已有温度、操作和化验数据，新增硬件只补缺口。pH 可先人工录入，不把在线光谱、压力和 CO₂ 作为所有容器的默认配置。

B 路线可先选 **1 条清洗回路或 1 类重复清洗任务**，记录阶段、时间、流量、温度、电导率及资源用量。选择对照时匹配设备、污染负荷、程序和产量条件。

上述数量是控制试点复杂度的建议，不是证明准确率、良率改善或投资回报的样本量。统计所需批次数应根据事件发生率、基线波动和待检测改善幅度另行计算。

### 3.2 不把两个月试点写成最终品质证明

| 阶段 | 建议安排 | 输出 |
| --- | --- | --- |
| 调研与基线 | 约 1–2 周，按资料准备情况调整 | 主问题、损失口径、点表、质量边界、初步报价 |
| 安装与核对 | 约 2–4 周，依停线窗口调整 | 测点验收、人工对照、时钟与批次关联、故障演练 |
| 影子运行 | 约 4–8 周起步，不影响原生产决策 | 提醒质量、缺失/漂移、操作负担、候选改进项 |
| 独立验证 | 按完整工艺周期和所需独立批次数延长 | 冻结规则后的结果、质量与收益复核 |

古越龙山公开介绍的部分传统工艺有 90 余天发酵及更长陈储周期，因此短期观察不能替代对应终点的质量验证。[S03](evidence-register.md#s03) 若首期只覆盖早期阶段，结论必须限定为该阶段。

## 四、实验设计：避免“看起来有效”

### 4.1 基线、规则和对照先确定

开始前定义异常类别、判定人、可采取的动作和质量约束。优先以独立化验、维修记录或经审核的工艺偏差记录作为参考，不让模型给自己生成标签。

影子运行阶段先不改变生产。随后经工厂批准，对匹配工况进行分批或分阶段验证；无法随机安排时，记录配方、设备、季节、人员、产量等混杂因素，并明确因果归因的限制。

同一缸的分钟数据、同一样品的重复光谱，不是独立生产批次。训练、参数选择和最终验收应按批次/时间分开；最终验证数据不再用于调阈值。近红外研究的样本结构正说明必须区别“光谱条数”和“生产批次数”。[S06](evidence-register.md#s06)

### 4.2 先验证数据，再验证模型

定义有效数据覆盖率：

```text
有效数据覆盖率 = 有效且在规定时效内到达的记录数 / 按事先采样计划应产生的记录数
```

停机、维护等排除条件在试点前约定，不能事后删掉表现不好的时段。迟到补传可以计入完整性，不能冒充实时预警可用性。设备离线、超校准期、异常值与模型超出适用范围分别标记。

工程验收可先讨论例如 **有效覆盖率不低于 99%**、关键操作均可追溯等候选目标，但这些是待确认门槛，不是行业标准或现有能力。测量精度按工艺可接受误差与参考仪器不确定度共同确定，不直接从 ADC 位数推导。

### 4.3 提醒系统怎么验收

| 指标 | 口径 | 常见误判 |
| --- | --- | --- |
| 提醒准确率 | TP / (TP + FP)，由独立复核判定 | 把工程师点了“已读”当作提醒正确 |
| 异常召回率 | TP / (TP + FN)，需独立异常清单 | 只统计被系统发现的异常，漏掉 FN |
| 提前量 | 原流程可发现/处理时刻减去首次有效提醒时刻 | 与最终报告生成时间比较，夸大提前量 |
| 误报负担 | 每容器日/每清洗任务误报数及处理分钟数 | 只给总体准确率，隐藏大量无效提醒 |
| 可执行性 | 有明确动作且被负责人确认的提醒占比 | 提供泛泛的“请检查设备”也算有效 |
| 结果改善 | 在匹配条件下的实际损失或复核时间变化 | 将每次提醒都估算成避免整批报废 |

发生频率很低的异常，在短试点内没有出现，不能得出“召回率 100%”。可回放历史数据检查逻辑，但历史回放与前瞻性现场验证要分别报告，不用合成异常代替真实效果证明。生产线上不为测试而人为制造危险或污染。

### 4.4 近红外和电子鼻的额外验证

近红外需同时报告单位、偏差、RMSE、极端误差、样本范围和参考方法；按独立批次检查漂移。电子鼻需给出每类混淆情况、未知类处理和跨设备/时间表现。不要只提交 R² 或整体准确率。[S04](evidence-register.md#s04) [S05](evidence-register.md#s05)

比较参考设备与候选小型设备时，使用实际采集的数据，而不是只在高端仪器数据上裁剪波段。维护频率、取样/清洗耗时及无效读数比例也纳入成本。

## 五、收益口径：减少了什么，才能算什么

材料收益基于可干预工序的净损耗改善，扣除新增取样、返工与耗材。质量降级造成的价值变化，与材料报废避免额分开核对，防止把同一批酒重复计价。

水电汽收益按同类清洗任务或每单位合格产出归一化，并使用实际计量与结算单价。程序、温度或流量变化只有在满足同一质量要求时才能计作改善。锅炉燃料与自产蒸汽不能在同一边界重复计费。

人工节省若没有减少加班、外包或其他实际支付，只记录为释放工时，不直接算工资现金节省。计划外停机收益须有产能约束与实际损失依据，不能把所有停机分钟都按销售额折算。

```text
年度净现金收益 = 可核实材料节省 + 可核实公用工程节省
               + 其他不重复计算的现金改善 - 年度新增运维费用

简单回收期 = 一次性安装投入 / 年度净现金收益
```

净收益小于等于零时，不报告有限回收期。正式决策还应考虑资金时间价值、爬坡期、设备寿命、替换投资、税费和残值；下方演示不包含这些因素。

## 六、演示测算：这些数字全部是假设

目的不是估价，而是展示怎样用自己的数据反推项目需要达到的最低效果。

| 参数 | 演示值 | 定义 |
| --- | ---: | --- |
| 一次性安装投入 | 120,000 元 | 假定完整安装投入，不是芯片采购价或供应商报价 |
| 年度新增运维 | 24,000 元 | 假定校准、耗材、服务等年度现金支出 |
| 年度可干预材料成本基数 | 8,000,000 元 | 仅目标范围，不直接使用公司全部成本 |
| 年度可计量公用工程成本基数 | 300,000 元 | 与材料成本不重叠 |
| 目标简单回收期 | 2 年 | 演示决策要求，不是行业惯例 |

三种情景的节省率同样均为假设，不代表对项目成功概率的预测：

| 情景 | 材料节省率 | 公用工程节省率 | 年度毛节省 | 年度净收益 | 简单回收期 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 保守假设 | 0.2% | 2% | 22,000 元 | -2,000 元 | 无正年度净收益 |
| 中间假设 | 0.5% | 5% | 55,000 元 | 31,000 元 | 约 3.87 年 |
| 乐观假设 | 1.0% | 8% | 104,000 元 | 80,000 元 | 1.50 年 |

这组计算说明：相同硬件投入，只要实际损失改善不同，项目可能回本，也可能连运维都覆盖不了。不能只展示乐观情景。

在公用工程节省率假定为 5% 时，达到两年简单回收期所需材料节省率为：

```text
(120000 / 2 + 24000 - 300000 × 5%) / 8000000
= 0.008625
= 0.8625%
```

需要进一步问：现场实际可减少的损失有没有这么多？这些损失是否处于本项目控制范围？若可减少的损失上限本身不足，就应降成本、缩小范围或放弃，而不是提高模型预期。

### 复算方法

```bash
python3 scripts/roi_model.py

```

## 七、安全与质量边界

第一期不改动安全联锁，不由 AI 执行温控、加料、阀门和清洗程序；网关故障或云端断联不得影响原有生产。工业控制的可靠性和安全需求可参考 NIST OT 指导文件，但具体措施与合规要求必须由现场审核。[S14](evidence-register.md#s14)

新增探头、支架、取样管路和电气设备需经过工艺、质量、设备与安全人员确认。不能因为电导率、pH 或气味模型正常就放行产品；CIP 过程监测不替代清洗验证和检验。未纳入验证范围的场景应明确拒绝给出确定判断。

原始配方、生产数据与人员信息默认不写入本公开仓库。本仓库保存公开研究与脱敏后的方法文件；后续现场数据应进入工厂批准的存储环境。

## 八、继续、调整与停止条件

**继续扩大：** 数据可靠，提醒能改变具体动作，质量没有退步，在独立批次/任务上有可复核改善，维护负担与安装成本可接受。

**调整范围：** 发酵异常样本不足但已有计量收益，或数据关联已改善复盘效率，应按已验证价值单独评估，不能继续宣传未验证能力。

**停止或暂缓：** 长期缺少质量标签、无法干预发现的问题、误报处理负担过大、卫生安装不通过、现有系统可低成本满足需求，或实际可减少损失不足以覆盖费用。

最终交付应包含原始口径、基线、验证集划分、独立复核、收益计算和未解决问题；不以一张看板、一次演示或一次“提前发现”作为项目全面成功的依据。
